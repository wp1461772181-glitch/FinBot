# 盒上补上知识库的「存」这一头

owner 11-28：「写方案然后执行去吧」。背景是 11-28 的排查。

## 现状（11-28 盒上实测）

- **查**：`finbot-rag-slim`（盒上 `/opt/finbot/rag-slim`，不在仓库里）每次检索时调 OpenRouter 的 `baai/bge-m3` 给问题做向量，再查 pgvector 的 `chunks` 表；关键词检索 BM25 是启动时整表读进内存建的。这一头一直在用。
- **存**：原来在 Mac 那边的检索服务上跑（本地 BGE-M3 加 Milvus）。11-13 搬到盒上时，瘦后端只做了检索和重排，盒上没有写入的路：
  - API 的 `RAG_INDEXING_ENABLED=false`，`RAG_MODEL_PATH` 还指着 Mac 上的目录；
  - 把申报、新闻、上传材料、分析同步成知识库文档的后台循环（`source_sync.start_source_sync`），要先有本地模型运行时才会启动，盒上一直在空等；
  - 盒上 API 的环境里没有 `tokenizers`，也没有 bge-m3 的分词器文件（切块要用它数 token）。
- **数字**：
  - 知识库文档最新一篇发布于 11-02；
  - 向量库 6,026 条，代际 `8abb…`，和现在的代码一致，最新一条是 11-03 07:57；
  - 主库里同一代有 6,051 块已索引、484 块一直挂着没索引；另有 4,751 块属于更早的一代，已经作废。
- **价格**：OpenRouter 上 `baai/bge-m3` 每 token 0.00000001 美元。一份大 10-K 约 25–30 万 token，合 0.3 美分；全部补齐也不到 1 美元。

## 做法

不另起炉灶：沿用现有的同步、切块和索引任务（`sync_source_batch`、`ingest_documents`、`index_pending`），只给它们换上盒上能用的三个零件。

1. **分词器**：`tokenizers` 直接读 bge-m3 的 `tokenizer.json`，和原来 `AutoTokenizer` 用的是同一个文件，数出来的 token 一样，切块结果也一样。文件从 Mac 本地拷到盒上的 `/opt/finbot/knowledge/`；盒上 API 的环境里装 `tokenizers`。
2. **向量化**：调 OpenRouter 的 `baai/bge-m3`，和检索时用的是同一个模型，存和查的向量一致。一次发一批，结果归一化（库里原有的向量模长都是 1）。每次调用记进模型用量账本，用途沿用已有的「知识库」（`knowledge`，任务名 `knowledge-index`），带上 token 数，方便核对花费。
3. **向量库**：写盒上 pgvector 的 `chunks` 表，列和瘦后端读的一一对应。写入是按 `id` 覆盖；写之前先核对表里只有当前这一代，否则拒绝写入。

**密钥不复制。** OpenRouter 的密钥和 pgvector 的连接信息，都从盒上已有的两个文件里读：`/opt/finbot/rag-slim/env` 和 `/opt/finbot/pgvector.env`。设置里只写这两个文件的路径，代码不打印、不另存任何密钥。

**后台循环 `knowledge-index`**：每 2 分钟一次。先把各类来源各同步一小批，再索引最多 40 块。三个零件里缺任何一个（文件不在，或依赖没装），就只记一行日志、什么都不做，所以本机、CI 和影子环境都不受影响。开关 `FINBOT_KNOWLEDGE_INDEX`，默认开。

**影子实测不碰线上向量库。** 表名可以配置（`RAG_PGVECTOR_TABLE`）。影子环境里建一张结构相同的 `chunks_shadow` 表，跑完删掉。

## 有意不做（写明）

- **瘦后端的关键词检索要重启才认新块。** 它的 BM25 只在启动时建一次。新块入库后马上能被向量那一路检索到（混合检索本来就两路并用），关键词那一路要等瘦后端下次重启。瘦后端的代码不在仓库里，这次不去改它。上线时补齐数据后手动重启一次；以后要不要定时重载，单独定。
- **284 份只登记了目录的历史申报，这次不抓正文。** 它们是早年只登记了目录的旧申报，最近的申报都已经抓了。要不要补抓，单独定。
- **旧一代的 4,751 块不清理。** 它们不在向量库里，也不影响检索。

## 验收

- **相关测试：** 三个零件和后台循环的单元测试，不连网、不连真实库；全量测试。
- **影子实测：** 用一份 11-03 以后的真实财报跑通「同步 → 切块 → 向量化 → 写进 `chunks_shadow`」，用 token 数核对花费，并用 pgvector 查一次，确认新块查得回来。
- **上线：**
  1. 发布后看后台循环把缺的补齐，盯一下向量库条数和用量账本；
  2. 重启瘦后端一次；
  3. 用 `ruler.run ask` 问一句只有新财报里才有的内容。
- **审查：** 普通档，用 Sonnet。这次碰的是入库，会写线上向量库，所以影子实测必须先做。

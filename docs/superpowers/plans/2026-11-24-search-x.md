# Search X Implementation Plan — a tool that searches recent posts on X

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** FinBot can find what was posted on X in the last seven days, shows it as what it is (an unverified post, by whom, when), and cites it like any other source.

**Architecture:** One new read tool, `search_x`, in the tool catalogue. It calls X's official API (`GET https://api.x.com/2/tweets/search/recent`, app-only Bearer token from the server's environment) and returns rows shaped like the rows of the existing news search, so both engines number and cite them through their existing paths. Today the only web source is a general web search (Tavily), which does not index posts on X.

**Tech Stack:** Python 3, httpx, pydantic, pytest; one label line in the frontend.

**Spec:** the owner's request of 2026-11-24 (「让他去推特上搜，基本搜不到什么信息」) and `docs/finbot-new-kernel-plan-2026-11-22.zh-CN.md` section 4.11 on source order (official filings and announcements before news, news before social platforms).

## Global Constraints

- **The token never leaves the environment.** It is read from `X_BEARER_TOKEN` at call time and used only in the `Authorization` header. It never appears in a log line, an exception message, a tool result, an audit, an endpoint response or a test fixture's output. Errors from the HTTP client are reduced to a short code before they are logged or returned (a URL or header must never be echoed).
- **Owner only.** A guest is never offered the tool and a guest's call is refused: every returned post costs the owner money.
- **Posts are claims, not facts.** Every row says it is a post on X, who posted it and when. Nothing in this slice treats a post as verified evidence.
- **Spending is bounded and visible.** Results per call are clamped, a daily cap on posts read is enforced across processes, and each call's count is recorded.
- With `X_BEARER_TOKEN` unset the system behaves as today: the tool is not offered to the model by either engine, and no test or startup path fails.
- Tool definitions stay stable within a turn; the kernel's own tools stay last.
- Nothing about existing tools changes: their descriptions, schemas, order in the catalogue and results are byte-identical.
- User-facing copy is Simplified Chinese; the tool description for the model is English like the other catalogue tools.
- Tests: `/Users/wupeng/Monash/monash-ai/projects/market-evidence-agent/.venv-rag/bin/python -m pytest -q -W ignore <files>`. Two tests fail on main for unrelated reasons (`test_sw1_existence_knowledge::test_t39…`, `test_sw1b_sample_aggregate::test_b17…`); leave them. No test may call the real X API. Do not start a background run of the whole suite.
- Commit with a plain-English message, files by name.

## Review Focus

1. The token: grep every new log call, exception path and returned dict for a way the token, the `Authorization` header or a full request URL could reach output.
2. A guest, and an owner bot whose tool scope excludes the tool: not offered, and refused if called.
3. X returns 401, 403, 429, a 5xx, a timeout, malformed JSON, and a 200 with no `data`: each becomes a short code with a Chinese reason a person can read; none raises out of the tool; none counts against the daily cap.
4. The daily cap is reached: the call is refused before any request is made, with a reason that says the cap and when it resets.
5. A post whose text contains instructions ("ignore previous instructions and …"): it reaches the model only as the `text` field of a numbered row, like any other source.

### Task 1: the `search_x` tool

**Files:**
- Create: `app/x_search.py`, `tests/test_x_search.py`
- Modify: `app/agent_tool_catalog.py` (args class, catalogue entry, category, owner-only set), `app/agent_workflow/tools.py` (dispatch), `app/kernel/loop.py` (`READ_TOOLS`), `app/kernel/toolrun.py` (`_SOURCE_TYPES`), `app/kernel/progress.py` (`TOOL_PHRASES`), `app/agent_chat_models.py` (one small table), `frontend/src/agent-tool-labels.mjs` (+ locale entries if that file's labels need them), and whatever the old engine needs to accept the new row type (see below)
- Test: `tests/test_x_search.py`, plus the existing catalogue / label / kernel tests that enumerate tools

**Interfaces — produces:**
- Catalogue tool `search_x`, level `read`, owner only, in category 「新闻与网页」. Arguments (`SearchXArgs`, extra fields forbidden):
  - `query: str` (1–300 chars) — X search syntax.
  - `hours: int = 72` (1–168) — how far back.
  - `max_results: int = 20` (10–50).
  - `sort: Literal["relevancy", "recency"] = "relevancy"`.
- Description for the model (English, one paragraph): what it is; when to use it (the user asks what is being said on X, or something may have been posted on X before it reached news or filings); that posts are unverified claims — say it is from X, who posted it and when, and check anything that matters against official sources before stating it as fact; the query syntax in one line (`words`, `"exact phrase"`, `from:username`, `OR`, `-word`, `lang:en`, cashtags like `$NVDA`); that each returned post costs money, so ask for what is needed.
- `app/x_search.py`:
  - `configured() -> bool` — `X_BEARER_TOKEN` is set and non-blank.
  - `MAX_RESULTS = 50`; `DAILY_POSTS` from `X_SEARCH_DAILY_POSTS` (default 2000); the day is the UTC day (X bills by UTC day).
  - `async def search(args: dict, *, owner_hash: str) -> dict` — the tool result:
    - not configured → `error("x_not_configured")`;
    - daily cap reached → `error("x_daily_cap")` with `reason` 「今天搜 X 的额度（N 条）用完了，UTC 零点后恢复。」, no request made;
    - request: `GET https://api.x.com/2/tweets/search/recent` with `query` (the model's query with ` -is:retweet` appended unless it already mentions `is:retweet`), `start_time` (now − hours, RFC 3339, never older than 7 days minus a minute), `max_results`, `sort_order`, `tweet.fields=created_at,public_metrics,lang,author_id`, `expansions=author_id`, `user.fields=username,name,verified,public_metrics`; header `Authorization: Bearer <token>`; timeout 15 s; one request, no pagination;
    - failures → `error(code)` with a Chinese `reason`: 401/403 `x_auth_failed` 「X 的访问令牌无效或没有搜索权限。」; 429 `x_rate_limited` 「X 那边限流了，稍后再试。」; timeout / connection `x_timeout` 「连接 X 超时。」; anything else `x_unavailable` 「X 的搜索这次没有成功。」;
    - success → `{"ok": True, "data": [row, …], "source": "x", "meta": {"query": <as sent>, "window_hours": hours, "returned": n, "daily_remaining": k}}`; zero posts is `ok` with an empty list.
  - A row: `{"id": <post id>, "source_type": "x_post", "title": "@<username>：<first 60 chars of the text, one line>", "url": "https://x.com/<username>/status/<id>", "published_at": <created_at>, "author": {"username", "name", "verified": bool, "followers": int}, "text": <full text>, "metrics": {"likes", "reposts", "replies"}, "note": "X 上的帖子，未经证实"}`. A post whose author is missing from `includes.users` uses `i` as the username in the URL (`https://x.com/i/status/<id>`) and `@未知` in the title.
  - Usage: a table `x_search_usage` (`day DATE`, `owner_hash`, `posts INTEGER`, primary key day + owner) incremented by the number of posts returned, in the same transaction that checks the cap for the next call; created by the app's usual `create_all`.
  - Logging: one line per call with the owner-less facts only — result code, posts returned, the day's total. Never the query text (it can hold what the user is researching), never the token.
- Kernel: `search_x` is in `READ_TOOLS` (after `search_configured_news`); `_SOURCE_TYPES["search_x"] = "x_post"`; `TOOL_PHRASES["search_x"] = "搜 X"`. It is offered only when `x_search.configured()`.
- Old engine: the tool is reachable the way `search_configured_news` is (its category via `load_tools`), only when configured. Its rows must be numbered and citable by the old engine's evidence path: read how `search_configured_news` rows (source type `configured_news`) pass through `app/agent_workflow/evidence.py` and the turn (`direct.py`), and make `x_post` rows pass the same way with the smallest change. If the old path cannot take a new source type without changes to its gates that you cannot make safely, STOP and report (status `NEEDS_CONTEXT`) with what you found — do not weaken a gate.
- Frontend: `frontend/src/agent-tool-labels.mjs` gains `search_x: "X 帖子搜索"` (and the English locale entry the labels test requires); if the sources panel needs a display name for the `x_post` source type, add 「X 帖子」 where the other source types are named.

# 阶段 4f：角色模板——「短线」「定投」「基金经理」，只是起步的记忆和设置

日期：2026-11-25（夜）。分支 `claude/stage4f`（在 `claude/stage4e` 之上，4e 在 4d 之上；合并顺序：4d → 4e → 4f）。计划 `docs/superpowers/plans/2026-11-25-stage4f-role-templates.md`（Opus 规划席写的，原样入库）。

## 结论

- **记忆页「它眼中的你」里多了「用模板起步」**：三张卡（短线、定投、基金经理），每张写明会加几条记忆、几个简报、几个技能。点「看看会加什么」，对话框里逐项列出：每条记忆的原文、每个简报的名字和时间（用大白话，如「工作日 09:00（美东时间）」）和内容、每个技能，以及「已有、沿用」和「放不下」的项，每一项都可以取消勾选，目标可选「全局 + 助理」或你自己的某个 bot。点「应用」才写。
- **写进去的全是普通的记忆和设置**，走的是你自己页面用的同一批服务：记忆条目（来源标为你手写，所以季度整理不会把它们归档、月度整理不会再重复提议）、例行任务里的简报、技能库里的技能，以及加进 bot 常用技能的那几个。画像里这些条目带「模板·短线」的标签，条目下写「你在 M月D日 选用模板「短线」时加的」，不再显示一段原话。模板文件之外，没有任何一行代码认识「短线」「定投」或「基金经理」；内核、提示词、值班叫醒读到的就是你手写时一样的记忆。
- **绝不动你已有的**：同样的记忆条目（同文同类）、同名的技能（启用中的，含内置）、同名的任务，一律沿用并如实告诉你；同名但是草稿或停用的技能，不动它也不创建，告诉你。某一层记忆放不下（已有加新增超过 30 条），记忆这部分整体不写、一条都不挤掉你的（简报和技能照常写）。常用技能最多 20 个，放不下的跳过并说明。连续应用同一个模板，第二次什么也不创建。
- **随时可以整体撤掉**：「撤掉」列出这次应用写进去、现在还在的每一项（你改过字的显示改后的字，已经被你删掉的显示「已经不在了」），逐项可以勾选保留。只撤它记录过的东西；你自己加的、内置技能，一概不碰。撤销后这次应用标为已撤掉。
- **模型也能做，但要你点确认**：对话里说「我是做定投的，按定投帮我设一下，简报不要」，会出一张确认卡（第二级，仅 owner、仅新内核），逐项列出要写的东西，你点了才写；说「把那个模板撤掉」同理。访客和旧引擎看不到这两个操作。
- **页面和卡片如实说明模板够得着什么**（固定的几句话）：盯防类的几条会在每次回答和值班判断时读到；值班现在只记录、不主动发消息（要看 `FINBOT_DUTY_MODE`，打开后这句话自动消失，这一片不碰这个开关）；价格异动的默认提醒（哨兵）这一版不随模板改变；每条简报每次运行会调用一次模型、记在用量里，可以不勾；持仓、计划价位和你对公司的看法，还要在对话里慢慢告诉它。
- 三套模板的内容逐字照计划附录（记忆、简报指令、技能步骤、输出格式、允许的工具、时间表）；审查时用脚本对照过。

## 计划里「待 owner 定」四条，按计划的推荐先行

1. 三套模板的具体内容：先按附录上线，之后改字是改数据、不动代码。请 owner 看一眼「基金经理」里的 25% 单只占比线和 3% 单日回撤线（规划席定的起步值）。
2. 不带「硬规则」（哨兵的价格规则现在不分人、没有开关；等第五阶段做成每人可调之后，再把预置规则加进模板）；页面如实写了「价格异动的默认提醒不随模板改变」。
3. 不碰值班开关；页面如实提示值班现在只记录。
4. 简报默认勾上，每次运行的花费在说明里写明，可以不勾或之后在例行任务里暂停。

## 和计划的差异（及理由）

1. **工具参数里模板用 `str`，不用枚举。** 计划要求「`app/` 里除模板文件外没有任何地方出现模板 id」（有测试 grep 这一点），所以操作的参数不能写成 `Literal['short_term', …]`。参数收「模板 id 或中文名」（短线、定投、基金经理），服务端对照 `TEMPLATES` 解析，认不出来就拒绝并告诉模型「只带 operation 调用一次看有哪几个」；那次查询返回每个模板的 id、名称、每项的 key。
2. **一条红测的期望按计划改了。** 红测里「基金经理在定投之后应用，常用技能还在的有 2 个」假设三个都记录；计划写的是「实际加进去的才记录」：「财报速读」已经在定投那次加过，基金经理这次没加，撤销时也不该去动它。所以期望是 1（「同行对比」）。
3. **确认卡冻结的内容要传到按下那一步。** `tools.py` 原来只对 `create_bot`、`update_bot` 把卡片上冻结的 `fields` 递给执行；两个新操作也加进去了。不加的话，「撤掉模板」不带 id 时按下去会重新算「最新一次」，而不是卡片上展示的那一次。是我自己的测试发现的（`0457afc`）。
4. **前端按后端真实形状读。** 前端子代理是按计划里没定死的形状写的（行里 `text`/`gone`，`still_there` 按 `profile_items/tasks/skills`，`created` 是对象），后端实际返回行里 `label`/`there`/`note`、`still_there` 按 `memory/brief/skill/usual`、`created` 是列表。不改的话撤销对话框里的名字会是空的、「还在：…」的计数全是 0。独立审查时我发现并改了（`f770815`），辅助函数两种形状都认，补了 3 项测试。
5. 钉住旧数量的测试跟着改：新内核仅有的操作 12 → 14，`act.OPERATIONS` 38 → 40，两个操作加进安全探针清单。旧引擎的工具定义哈希没动（测试钉着，通过）。
6. 登记表：预览是只读（`_no`），应用和撤销对应两个操作。

## 审查

- 实现：后端 task 1–3 由我自己小步写（子代理在今晚多次被平台替换打断，只留下了红测）；前端由子代理写。
- 独立审查（只读子代理 + 我补完，记录在 `.local/review4f/report.md`，未入库），发现并处置：
  - **F1（已修，`aa872b1`）**：你的常用技能列表里如果有一条已经失效的技能（比如加进去后又被删了），列表整体改不动；撤销之前会把这些常用技能也报成「已撤掉」，实际没撤。现在把它们列进「留下」并写明原因，应用时也说清为什么没加进去。
  - **F2（裁定不是缺陷）**：技能库的 `delete_skill` 不会清掉别的任务上的 `skill_id`。计划明说「不加新行为，只在测试里钉住」；页面和卡片已经提示「还有 N 个别的例行任务在用它」。
  - **前后端形状不匹配**（上面差异 4，已修）。
  - **预览与应用一致**：没发现问题，用 15 项测试钉住（3 个模板 × 5 种取消勾选组合：预览列的 = 应用创建的）。
  - 逐项核对过没问题的：从不动你已有的数据（同文不同来源的条目、满层里有推断条目、同名内置技能、同名停用技能、同一个模板应用两次）；逐字照附录；系统提示词与旧引擎定义不变；访客拿不到这两个操作；值班那句话跟随 `wake.mode()`、没有任何代码读写环境变量。
  - 已知、未修：同时发两次「应用」（两个线程并发），简报没有按名字去重，理论上可能创建两个同名简报；记忆和技能有重复保护。确认卡的按下一次性、页面的应用按钮在请求期间禁用，所以这个竞争很难触发，记在这里。

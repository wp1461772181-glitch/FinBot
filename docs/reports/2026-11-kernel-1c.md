# 新内核 1c 实测：它能动手了（操作目录、写操作三级、确认卡）

日期：2026-11-24。分支 `claude/kernel-stage1c`。影子环境（11-23 备份恢复的库、盒上 :9031，库是临时副本，写入不影响线上），
模型 claude-haiku-5-5。原始结果在 `docs/reports/2026-11-kernel-1c/run1`。

## 结论

- **新内核可以改数据了。** 一个工具「动手」（`act`）进所有写操作；它的说明就是操作目录，27 个操作分三级。
- **三级放行在真实模型上都按设计走：** 记住偏好直接生效；记交易、设可用资金出确认卡，点了才写；第三级的卡写明代价。
- **没点卡就不会执行。** 打字「同意」、重复点同一张卡、藏在资料里的指令，都没有造成任何写入。
- **点卡之后它接着把事做完。** 「记一笔买入，再告诉我现在的仓位」：点同意后同一轮入账并报了仓位。
- **原有能力没受影响。** 尺子 85/86，回忆题 24/24，整轮中位 5.6 秒（1b-2 是 5.1 / 5.4 秒）。
- 实际的写入一行没重写：确认卡的生成、加锁执行、每个操作的落库，全部复用旧流程里的那套。

## 审查里查出并修掉的

1. **读过资料后的「记住」不再直接生效。** 自动安全审查指出：第一级操作由内核自己批准，网页里的话可能骗它写进长期记忆。
   改成按来源判断：这一轮还没读过任何资料时直接做；读过之后提出的，进确认卡。点卡后续做的那一轮也算读过。
2. **点卡后交给模型的执行结果改成明确标注的资料**（一段 JSON，带长度上限），系统身份的消息里只留固定句子。
3. **旧流程生成的卡在新内核下被点，不执行。** 定时任务永远走旧流程，它放进收件箱的建议卡有的需要两步确认；新内核不认识的卡一律提示换用其他 bot，卡保留。
4. **点卡执行成功后模型出错，不再告诉用户「失败」。** 由代码直接写一句「已执行：……」，避免用户重复提交。
5. **五张第三级的卡原先没写清对象**（撤回哪份文档、审核是通过还是拒绝等），已补上。
6. **打字「同意」时模型会重复出卡。** 原因是它看不到卡上是什么；现在系统把卡片内容作为资料告诉它。
7. 另外：令牌必须和正在等待的那张卡对得上才执行；可恢复的拒绝（如登录过期）不把卡丢掉；过期的卡不再提示「还在等」；每次动手都留一行痕迹，写成功后即使整理结果出错也如实报告成功。

## 没解决的

- **这一片不支持的操作：** 保存网页为来源、修订预测（都需要服务端先做准备）、主动问用户、用技能、发 Telegram 通知。模型会说现在做不了。
- **一张卡承载一轮里的所有提议，** 用户不能只同意其中一部分。每一项都列在卡上。
- **打字回复时会把等待中的卡重新发一遍，** Telegram 上会重复出现按钮，最多持续十分钟。
- **模型常常先猜参数、被退回、再改对，** 多花一秒左右。查格式也要多一次往返。
- **影子环境的 API 有一次在评测中途因内存超限被杀**（上限 600M，3 分钟内从 330M 涨上去）。重跑整套 86 轮加全部探针，
  内存全程 340~389M，没有复现，原因没有查清。影子环境的上限已放宽到 1G；线上 API 没有这个上限，当时常驻 443M。
- **线上没有做过写入测试。** 所有写入都在影子库里做的；线上的写入要动 owner 的真实数据，留给 owner 自己试。
- **确认卡在网页、Telegram、微信上的显示没有重新看过。** 卡的格式和旧流程完全一样，按理不需要改动。

# 6a 剩下的回合也走新内核

计划：`docs/superpowers/plans/2026-11-28-stage6-kernel-everywhere.md`。设计稿第十二节第 6 阶段。

## 做了什么

六个 bot 11-24 起已经在新内核上。这一片把剩下还走旧流程的三处也切过来：

- **定时任务。** 以前无人值守的回合一律走旧流程，现在跟着它的 bot 走新内核。
- **不带 bot 的回合**（访客、对话线之外的旧对话、目录模型直连）：以前只有 `FINBOT_KERNEL_DEFAULT=v2` 才走新内核，现在默认就走。
- **新建的 bot**：`engine` 默认为空，以前因此走旧流程，现在走新内核。

新内核为定时任务补上的东西：

- **工具：** 读工具（不含搜 X，旧流程的定时任务也没有）、`act`、`notify_telegram`、技能、清单、升档。没有 `ask`（没人能回答），也没有插话处理（没人插话）。
- **写操作进收件箱。** 定时任务里 `act` 什么都不当场执行，第一级（研究队列）也一样。一次运行提出的所有操作合成收件箱「待你确认」里的一条，就像对话里合成一张卡片；他在收件箱里点「生成确认卡」，卡片照常由新内核执行。要他勾选材料的预测修订放不进收件箱，会被拒绝，并说明原因。
- **能建议什么。** 沿用旧流程的规定（`grants.suggestion_operation`）：他的记忆和看法、持仓和资金、定时任务、技能、bot 和各项设置，只凭他自己在对话里说，定时任务不能建议。能建议的是研究队列、待审的申报，以及第三级操作（抓取、导入、分析、预测等）。被拒时，工具结果和系统提示都说明了原因。
- **`notify_telegram`** 由新内核接过旧流程的同名工具。收件人由服务端定，消息前面加 bot 名，受每日条数限制，没带编号的数字会被拒绝，这些都由 `agent_telegram.notify` 管。这个工具只给定时任务：他在对话里时，直接在回答里说就行。
- **提示：** 定时任务的系统提示末尾多一段说明：没人在看、没有 `ask`、写操作进收件箱、什么时候用 `notify_telegram`。

访客的系统提示多一句：哪些事只有所有者登录后才能做，访客要求时直接说明。旧流程的访客提示里有这一句，新内核原来没有。

**退回办法（直到 6b 删掉旧流程）：**
- 全部回旧流程：`FINBOT_KERNEL_V2=off`。
- 没指定引擎的 bot 和不带 bot 的回合回旧流程：`FINBOT_KERNEL_DEFAULT=v1`。
- 只让定时任务回旧流程：`FINBOT_KERNEL_ROUTINES=off`。
- 单个 bot 回旧流程：`engine=v1`。

新工具 `python -m scripts.routine_replay`：在影子库上建一个定时任务、按调度器的方式跑一次、打印结果，跑完删掉任务。`--press` 会把收件箱里的建议转成卡片，再经影子接口点「同意」。不载入影子环境就拒绝运行。

## 有意没做

- **每次运行的 token 上限（`token_budget`）。** 调用方今天不传这个值，旧流程实际上也没用到。
- **测旧流程本身的老测试**（接口夹具、验收测试等）改成显式用 `v1`，没有改写成测新内核的版本。它们在 6b 随旧流程一起删掉；新内核的同类行为已有各自的测试。

## 影子实测（11-27 15:43 的备份，这一片的代码，影子环境不设引擎变量）

| 场景 | 结果 |
|---|---|
| 定时任务：查苹果公告和行情，有新季报就建议做预测，有新消息就发通知 | 新内核；查了 4 样；判断没有新季报，所以没提预测、没发通知；简报进了收件箱 |
| 定时任务：发英伟达收盘价，并建议把 NVDA 加进研究队列 | 通知排进发件箱（影子环境没有桥，不会真发）；建议进了「待你确认」，标题「这是 Agent 的建议，不是你的要求：加入研究队列」；没有当场执行 |
| 定时任务 + `--press`：把 ORCL 加进研究队列 | 建议 → 转卡片 → 点同意 → 新内核执行，「ORCL 已加入你的研究队列」，库里的研究队列多了 ORCL |
| 不带 bot 的所有者回合（`ruler.run ask`，两句） | 新内核（状态 `succeeded`），首字约 4 秒；追问「那毛利率呢」接得上 |
| 访客：「帮我记住我持有 100 股苹果，然后告诉我苹果最新收盘价」 | 新内核；查了报价；说明访客身份记不了持仓，要所有者登录，没有假装记下 |

访客那一轮是在影子进程里直接跑的：接口上的访客要自己带模型和密钥，我不碰密钥，所以模型从服务端目录取，密钥只留在进程内存里。

实测中看到、不属于这一片的：
- **一处判断错误。** NVDA 那次说「11-27 美股休市」，实际 11-26 休市、11-27 是半日市。影子库是 11-27 收盘前的备份，最新收盘价确实是 11-25 的，但它给出的理由错了。
- **点同意后的回答还在接着回应定时任务。** 卡片的原始问题就是定时任务的指令，所以执行完以后，它又回应了一遍指令，比如解释「我没有对比上次的结论，所以不回复『无新消息』」。不影响执行，但读起来啰嗦。旧流程这条路也是用同一个原始问题。

## 尺子

基线题集 `baseline-v1` 跑一遍，影子环境不设引擎变量（也就是这一片的新默认）：**86/86 全过**。整轮中位 5.1 秒、P90 9.9 秒，首字中位 4.5 秒。之前几片是 85–86/86、整轮中位 5.1–5.4 秒，不低于基线。结果在盒上 `/opt/finbot/ruler-out/6a-20261128`。

题集问的都是不带 bot 的所有者回合。以前要设 `FINBOT_KERNEL_DEFAULT=v2` 才走新内核，这次不设也走新内核，正好验证了新默认值。

## 审查（Sonnet）

结论「不通过」，确认了四处问题，全部改了：

1. **（高）定时任务存的回答是几步文字拼起来的。** 新内核会先发出一步的开场白（比如「我先查一下」），调用工具前再收回（`answer_reset`）。运行器只累加文字、不认收回，所以回答前面会带着开场白。后果是「无新消息」不再被认成没有新内容，收件箱会多一条没用的简报。现在收到收回就清空，补了测试。
2. **（中）小助手能拿到 `notify_telegram`。** 定时任务里如果打开了小助手（默认关），读过外部网页的小助手可以直接给他发消息。已把它加进小助手不能用的工具。
3. **（低）定时任务提议保存技能，进收件箱后少了「存为草稿」一档。** 按上面的规定，定时任务现在不能建议保存技能，这条随之不存在。
4. **（低）一次运行的几个提议拆成几条收件箱项。** 一条对话同时只能挂一张卡片，后生成的会让前一张失效。现在合成一条，`agent_tasks.mint_card` 用全部操作出一张卡片。

修第 3 条时我发现一个审查没提到、更要紧的缺口：旧流程不许定时任务建议改他个人数据和设置的操作，新内核原来没有这条规定（见上面「能建议什么」）。已补上，也补了测试。

审查提出、按设计保留的：
- **状态口径。** 一次没读任何资料、凭已有知识写结论的定时运行，现在记为 `ok`；旧流程会记为「没有证据」。这样处理符合准则一（默认相信模型）。
- **线上没有遗留建议。** 线上收件箱里没有旧流程留下、新内核认不出的建议（已查，0 条）。

# 小助手默认打开（设计稿漏项第 5 条）

owner 11-28：「先修第 1 条，然后按顺序把其他的都做了」。设计稿 4.6：小助手多一种出错的方式（交代不清、结果转手时丢信息），所以「用尺子量过质量再默认打开」。

## 量了什么（影子环境，11-28 07:33 的备份，模型 haiku-5.5）

| | 小助手关（lookup-20261128） | 小助手开（helper-on-20261128） |
|---|---|---|
| 尺子 86 轮 | 85/86 | 85/86 |
| 答完中位数 / P90 | 5.3 秒 / 9.9 秒 | 5.3 秒 / 9.6 秒 |
| 出第一个字中位数 / P90 | 4.7 秒 / 8.4 秒 | 4.5 秒 / 7.8 秒 |
| 派小助手的次数 | — | **0** |

- 两边用的是同一套代码，只差这个开关。各项耗时都在零点几秒以内，算持平。没过的是同一道会来回翻的追问题。
- **另问了两道专门适合派活的题：** 「分别读英伟达、AMD、英特尔最近一季财报里关于资本开支和指引的说法」「微软、谷歌、亚马逊的云业务收入和增速」。模型都是一步发出 7 到 11 个并行读取，自己做完，同样没有派小助手（45 秒、36 秒）。

## 结论和做法

- **打开它不让任何东西变差。** 尺子分数和耗时持平，工具列表多一个工具，没有出现误用。
- **它自己干活的质量量不出来**，因为 88 轮里模型一次都没用它。设计稿 4.6 说「先做并行，小助手随后」，现在并行已经够用，模型就不派。
- **按设计默认打开。** `FINBOT_HELPER` 不设就是开，设成 `off` 关掉。以后模型真的开始派活时，后台「回答」栏能看到每次派活的经过；要是发现质量不行，一行配置就能关。
- 测试环境里仍然默认关（`tests/conftest.py`）：内核的大部分测试描述的是没有小助手时的工具列表，小助手自己的测试会显式打开。另有一条测试断言应用里不设开关时是开的。

# 阶段 5b-2：系统默认规则公开、可改；组合类默认规则；规则页面；灵敏度开关（2026-11-26）

计划 `docs/superpowers/plans/2026-11-26-stage5b2-preset-rules.md`。设计稿 §7.3「两套规则并行」「预置规则打算覆盖的方面」。分支 `claude/stage5b2-presets`（后台、哨兵、网页三部分合成）。

## 结论

- **系统默认的规则全部列出来，可以关、可以改门槛**：
  - 位置：网页「它眼中的你」→「它在帮你盯的」。在对话里说也行，比如「把单只占比的提醒改成 40%」，会出确认卡，写明原来和改后，并附 30 天试跑。
  - 止损价和新公告是硬保证，网页上没有开关，接口和对话都拒绝关闭，回答「这条是硬保证，不能关」。
- **新增的默认规则**（都可以关、可以改门槛）：

| 规则 | 默认 | 适用 |
|---|---|---|
| 单只占比过高 | 超过 25%：提醒 | 所有持仓 |
| 组合单日大跌 | 跌 3%：提醒；5%：加急 | 整个组合 |
| 连续下跌 | 5 个交易日：提醒 | 持仓和研究队列 |
| 52 周新高 / 新低 | 提醒；同一只股票一个月（20 个交易日）内最多一次 | 持仓和研究队列 |
| 成交量异常 | 平时的 3 倍：提醒 | 所有持仓 |

- **你的规则优先**：你给某只股票定了同一类规则，对应的默认规则就对它让位，网页上写明「对 INTC 让位给你的规则」。已过期或已完成的规则不再让位。
- **灵敏度三档**（安静 / 标准 / 灵敏，对应约 2.5σ/5σ、2σ/4σ、1.5σ/3σ），以及 5 分钟急动提醒的开关，在网页上直接切换，或在对话里说（出确认卡）。
- 这些规则的提醒都标「系统默认」，并写明在哪里可以关掉或改门槛。

## 实测（影子环境，11-26 备份）

- 「把单只占比的提醒改成 40%」：出卡，写明原来 25%、改后 40%，附试跑「过去 30 天会提醒你 4 次：TSLA 10-28、AAPL 10-29……」。点确认后，快照和网页接口都变成 40%，并标记「改过」。
- 网页接口直接关止损：被拒，返回「这条是硬保证，不能关」。
- 发现并修了一个**线上已有的问题**，单独发了热修复 PR #48：
  - 现象：在长对话里说「灵敏度调成安静」，模型回答「已经生效」，其实没有调任何工具。
  - 原因：PR #44 把你的问题放到最后，系统资料和你的话被合并成同一条消息，模型把你的话当成了系统资料。
  - 修法：在你的问题前加一句固定的分隔说明。
  - 对照：原样 0/5、旧顺序 2/5、加分隔 4/5；修好后真实一轮出了确认卡，重放 8/8。

## 审查修掉的问题

- 网页显示不出后台的中文拒绝原因（后台返回对象，网页只认字符串）。
- 已完成的一次性规则，网页上仍写着「让位」，哨兵实际已经不让位了。
- 52 周规则的试跑窗口和冷却边沿，与哨兵不一致。
- 英文界面有两处漏翻译。

## 已知局限

- 「连续下跌」把今天盘前或盘中低于昨收也算一天，所以盘前就可能报。
- 默认规则第一次生效时，已经成立的条件会各报一次。比如英特尔现在占比超过 25%，上线后会报一次。
- 灵敏度和 5 分钟急动的设置一旦存过，就以存的为准，不再看服务器上的环境变量。目前盒上没有设这两个环境变量。

# 阶段 3c：插话——它干活时你说的话，当场收下、这一小步结束就交给它

日期：2026-11-25。分支 `claude/stage3c`（在 3b 之上）。**还没有上线**：盒子停机，只在本地开发和测试。

## 结论

- **新内核的对话不再回「正忙」。** 它在回答时你再发一句，页面立刻显示「已收到」，这一小步结束时交给它，由它三选一：
  - **并入**（补充或修正）：已查到的资料都留着，回答把两句一起答，页面上那句标「已并入回答」，排在它并入的那个回答上方；
  - **另起**（另一件事）：单独开一件同时做，各自一条回答，每条回答上方引一行它答的是哪句；
  - **停下**（改主意）：这一轮马上结束，留下已写的部分和一句交代；它提过的卡片作废，不会再被按出去。
  它没表态时按「另起」处理（最稳妥：你的话总会有自己的回答），并记一笔。
- **正在写回答时插话：** 能逐字输出的模型（Anthropic 原生）在一小段之内停笔，带着半截内容做决定；其他模型一次性返回，就等这一步写完再交给它。已经发出的工具调用不丢。
- **同时最多三件**（`FINBOT_CONCURRENT_WORK`，默认 3）。第四件排队，告诉你「前面还有 N 件在做」；排队记录在 `agent_work` 里，重启不会悄悄丢掉（重启时按 3b 的规则标为被打断，并在对话里说一句）。
- **写操作的安全：** 停下时，这一轮里已经执行过的写操作会如实保留在对话里（下一轮模型看得到）；同一时刻全对话只有一张待按的卡片；「并入」的修正会撤掉之前的提议、换成新的，不会在同一张卡上叠出第二个操作；插话的文字和你打的其他字一样，不能直接触发任何执行。
- **每条回答都记下它答的是哪几句**（`reply_to`），消息接口返回每行的 id 和被回答那句的短引文；后台的单轮详情也显示。历史、摘要、分页都按「整轮」处理，几轮交错时不会把一轮切成两半。
- **Telegram 和微信：** 第二句不再在本地排队，直接交给服务器；桥先回「收到」，之后告诉你结果（已并入／已停下／单独回答并引一句原话／排队中）。旧流程的 bot 仍是原来的排队方式。
- **网页：** 回答时输入框不锁；每句话的状态依次是「发送中」→「已收到」→「已并入回答」/ 自己的回答 / 「已停下」/「排队中（前面 N 件）」；服务器没收下的显示「没有开始，可以重发」；停止按钮停最新的那个回答。
- 旧流程（访客、不带 bot 的入口）完全不变，仍回「正忙」。

## 测试

- 后端全量 5,142 项通过，失败的只有那两项一直存在的顺序相关测试。
- 前端 1,048 项通过，类型检查和构建干净；聊天类截图冒烟 24/24；七种状态在 1440 和 390 宽度各截了图。

## 没验证的（等盒子恢复）

- 测试 bot 上把五个场景各走一遍：查 NVDA 时补一句「顺便把 AMD 也比一下」（并入）；写回答时说「算了不用了」（停下，卡片不会再执行）；答 NVDA 时说「另外帮我记一下买了 10 股 TSLA」（另起，出交易卡）；三件在做时发第四件（排队，之后自动开始）；连发两句（都有决定，顺序不乱）。
- 网页和 Telegram 上各看一次真实的显示。
- 已知的取舍：几轮同时进行时共用同一个对话检查点；卡片已经保证只有一张，但「上一批搜索结果」可能被后结束的那一轮覆盖（影响「保存第一条」这类指代上一批结果的说法）。

# FinBot 新内核方案（终稿）

> 2026-11-23 定稿，供 owner 确认。这是方向稿，不是施工图：确认后再细化成可执行的任务。
> 现状数字来自 11-22 的线上记录和当时的 `origin/main`（`a9fca0c`）；微信桥是之后上线的（`649c96d`）。目标数字是我提的，等尺子建好后再校准。
> 第十五节列出了哪些是 owner 定的、哪些是我替 owner 定的。

## 一、要做成什么

**一句话：** 一个懂金融、也懂你的对话助手。你可以放心把信息和任务交给它，它知道你要什么，答得快，说的数字靠得住。

**给谁用：** 所有和金融打交道的人，从短线到长期定投，从散户到基金经理。不为每类人各做一套功能；内核对所有人相同，差别只来自它对每个人的了解。

**形态：** 对话是内核，这一点不变。主动提醒也是它在对话里先开口。

## 二、七条承诺

这七条既是设计目标，也是以后判断每次改动好坏的标准。

| 承诺 | 目标 | 现状 |
|---|---|---|
| **回得快** | 档案里有的简单问题：2 秒内出第一个字，10 秒内答完。需要现拉资料：30 秒内。超过 2 分钟的转后台，做完来找你 | 需要查资料的问题平均约 56 秒；不查资料的约 13 秒。「英伟达最新财报简单说说」11-22 实测 42 秒，数据当时已在库里 |
| **懂你** | 不反问本该知道的事；详略和格式符合你的习惯；思考深度自己判断 | 每轮先填一张十八项的分类表；30 天只记了 7 条记忆 |
| **记得准** | 问起以前对话里的细节，答案与原文一致 | 有关键词搜索和回看旧对话，没有语义搜索，细节多靠摘要 |
| **交得出去** | 交代的每件事都有回音：做完了、做不了、做到哪了 | 英伟达 11-17 财报提醒漏发；后台运行已有，但没有统一的任务状态，失败提示刚补上 |
| **可靠** | 数字对、有出处；没有就说没有；不悄悄失败 | 这块最强，但全压在回答那一刻，是慢的主要来源 |
| **能插话** | 补充后不重查已有资料；新任务不打断旧任务；2 秒内有回音 | 网页上再发一句会掐断当前回答；Telegram 上只能排队 |
| **看得见** | 它边做边用自己的话说发现了什么、接下来做什么；第一句一两秒内出现；等得久时说明在等什么 | 显示的是「指代消解、意图识别、模型决策」这类流水线环节，是系统贴的标签，不是它说的话 |

## 三、整体结构

```text
  SEC / 行情 / 新闻 / 日历 ──→ 档案（事实 + 你的看法）
                                 ↑ 存回去      ↓ 直接读
        事件 ──叫醒──→ ┌──────────────────────────────┐
  你 ──通道──────────→ │ 对话内核（一个只往后追加的循环） │ ──通道──→ 你
 （网页 / Telegram / 微信）└──────────────────────────────┘
                                 │
                                 └──→ 留痕（发出后再核对，只标注）──→ 后台
```

六个部分，各管一件事：

| 部分 | 管什么 | 章节 |
|---|---|---|
| **对话内核** | 一个朴素的循环。模型直接看到问题和工具，自己决定怎么做 | 四 |
| **档案** | 把事实提前整理好。回答时直接读，不再现场取证、现场计算 | 五 |
| **记忆** | 它对你的了解：你说过的、它归纳的、对话原文 | 六 |
| **后台值班** | 有事发生时叫醒它，由它判断要不要告诉你 | 七 |
| **消息通道** | 网页、Telegram、微信，可替换、可增加 | 八 |
| **留痕和后台** | 回答发出之后在旁边核对，只加标注；所有记录收在一个后台里 | 九 |

另有一件开发用的工具，**尺子**（第十节）：一套固定的真实问题回放，每次改动都量一遍七条承诺。

## 四、对话内核

### 4.1 一件事怎么走

现在的流程是：理解指代 → 分类填表 → 工具循环（每一步把全部材料重拼重发）→ 检查 → 重写。每一步都从头想，所以思考强度被步数放大。

新流程只有一个循环：

1. 开头是一段**固定不变**的内容：系统说明和工具定义。它每次都一样，模型服务商可以缓存，重复部分又快又便宜。
2. 接着是**你的背景**：它对你的了解、你关注的对象、最近的对话。
3. 然后是这件事本身。模型每调一次工具，结果**接在后面**，前面的内容不动。它的思考也保留，下一步是接着想，不是重新想。
4. 资料够了就写回答。

没有预先分类，没有分流，没有「申请加载工具」这一步。问「你好」它直接回，问财报它自己去读档案。

**叫醒它的有两种东西，走同一个循环：** 你的消息，和后台发生的事件（第七节）。

**对话越来越长怎么办。** 每个 bot 是一条不结束的对话线，不能无限追加。

- 一件事之内只追加，不改前面的内容。
- 新的一件事开始时，带上固定开头、你的背景、最近若干轮对话的原文；更早的只带摘要目录，要细节时读回原文（第六节）。
- 压缩在后台做，不在你提问时做。压缩后固定开头不变，所以缓存只在压缩那一次失效。

### 4.2 工具从六十多个减到十来个，但凡是能操作的它都能做

现在的工具是按系统内部功能切的，很细。新的按「人会怎么说」来切：

| 工具 | 做什么 | 取代现在的 |
|---|---|---|
| 看档案 | 一家或几家公司的数字、比率、同比环比、指引、最新财报摘要、你的看法 | 查财务数据 + 大部分「计算」 |
| 查行情 | 价格、涨跌、一段时间的走势 | 股价与报价查询 |
| 读原文 | 某份申报、新闻稿、电话会、已存资料的原文或某一节 | 申报、资料库的各种读取 |
| 搜索 | 新闻、网页、知识库，一个入口 | 新闻搜索、网页检索、知识库检索 |
| 拉取 | 系统里没有就现在去拿，拿到后存进档案 | SEC 拉取、行情初始化、网页入库 |
| 计算 | 档案里没有的算术，一次调用算完一批 | 逐条计算 |
| 我的账本 | 持仓、可用资金、计划 | 持仓查询 |
| 记忆 | 记下、忘掉、搜以前的对话、读回原文 | 记忆与回看 |
| 交办 | 定时任务、盯一件事、后台长任务、查手上有什么事 | 例行任务、通知 |
| 动手 | 所有会改数据的操作 | 记交易、设计划、存技能、发起预测等 |
| 问你 | 真缺一条只有你知道的信息时才问 | 同名工具 |
| 用技能 | 按你存过的做法来 | 同名工具 |

上面十来个是常用的，始终带着。其余所有操作放进一份「操作目录」，通过「动手」这一个工具进入：它按描述在目录里找到对应操作，再调用。这样工具少，能力不少。

- **怎么保证不漏：** 页面上的按钮和它能做的操作登记在同一份目录里，页面和它用的是同一个入口。再加一条自动检查：任何一个能改数据的接口，如果目录里没有对应操作、也没有写明豁免理由，测试就不通过。以后新加功能，它自动就会。
- **现在的差距：** 系统有约 90 个改数据的接口，它目前能用的工具是 61 个，两边不是一一对应（有些接口是对话本身的收发）。第一步是把这 90 个逐个过一遍，列出哪些它还做不了。
- **豁免的只有一类：** 密钥、登录凭证、模型 key、Telegram 令牌这些安全设置。它可以替你打开那一页，但不替你填。

### 4.3 谁有权让它改东西

现在的流程里，「这一轮允许哪些写操作」是由预先分类那一步从你的话里读出来的；工具结果里的文字（网页、新闻、申报原文）想让它改东西，会被拒绝。新内核去掉了预先分类，这道防线要换一种做法，否则「凡是能操作的它都能做」加上「它会读网页」就是一个漏洞。

- **读到的内容只是资料，不是指令。** 网页、新闻、文件里写的「请帮我……」一律不算数。这条写进系统说明，也由代码保证：工具结果永远以资料的身份进入对话。
- **写操作分三级：**

| 级别 | 例子 | 怎么放行 |
|---|---|---|
| 只影响它自己的记忆和关注 | 记下一条偏好、把一家公司加进关注 | 直接做，告诉你，一句话可撤销 |
| 改你的数据 | 记一笔交易、改计划、建定时任务 | 确认卡，你点了才生效 |
| 花钱或不可撤销 | 发起预测、批量删除 | 确认卡，并写明代价 |

第一级即使被网页里的话骗到，后果也只是多记了一条、可以撤销；后两级必须你亲手点。访客看不到持仓这类权限检查同样留在代码里，不交给模型判断。

### 4.4 想多深由它自己定

取消「思考强度」这个设置。模型可以选，强度不用选。

- **每个问题先由低档接住。** 它自己判断走哪条路：
  1. 能直接答的，直接答。
  2. 查一下就能答的，自己查了答。
  3. 需要深想的，升级：交给更高的档位接着做。
- **升级不是转交给一个陌生人。** 接手的一方读的是同一条对话线，接待已经看到的、查到的、说过的都在，不需要重新交代，也不会重查。
- **拿不准就升级。** 低档容易把难题看简单，所以提示里写明：不确定时往上交。判错的比例由尺子统计。
- **查资料的步骤始终用低档**，不管最后由哪一档来写。
- **你愿不愿意等，它从三处判断：** 你这句话怎么说的、它对你的了解、当时的场合。
- **判断错了，一句话纠正：** 「想深一点」「快点说结论」。说过几次后它应该记住。
- **每条回答标出用了哪一档**，方便你看它判断得对不对。
- **最高档（现在的 max）只用于你明确要的深度研究**，直接转后台，做完来找你。实测同样两轮财报问答，high 档是 54 秒和 64 秒，max 档是 276 秒和 450 秒。

实现上已经核对过：我们接的每家模型都支持按请求指定档位，只是档数不同。Claude 有现成的自适应思考；DeepSeek 只有关、高、最高三档；智谱只有低、高、最高且关不掉；OpenRouter 按各模型声明的档位。档数少的模型，「低、中、高」会有两档落在同一个实际档位上，这一点会如实显示。

### 4.5 看得见：边做边说，高档任务列清单

**它边想边说，像一个人在干活。** 比如对比微软和英伟达最近一季的财报，而系统里两份都没有，你看到的是：

```text
▮▯▮ 我先看看库里有没有这两份财报。
    都没有，我去各拉一份。
    拉到了。先各自理一遍要点，再对比。
────────────────────────────────
（正式回答）
```

- **这些话是它自己说的，不是系统贴的标签。** 现在思考时显示的是「指代消解、意图识别、模型决策、证据核验、修复回答」，那是流水线的内部环节。新内核里这些环节不存在了，这块位置就留给它说话，K 线动画保留，跟在最新一句旁边。
- **每句话说的是「我发现了什么、接下来做什么」。** 不出现工具名，不说空话。「都没有」是一个发现，这种话才有活人感。
- **句子往下叠，不是互相替换。** 你能看到它一路做了什么；发现它走偏了（比如把英伟达听成了苹果），可以立刻插话纠正。
- **回答出来后，这几句收成一行**（「查了 2 份财报 · 28 秒」），点开还能看。刷新页面后也在。
- **第一句在一两秒内出现。** 接住问题的是低档，它的第一句话就是你最先看到的东西。
- **等得久时补一句。** 某一步超过十秒左右没有新动静，系统如实补一句在等什么（「SEC 那边有点慢，还在等」）。

**这句话怎么来：跟着工具调用一起来。** 每个工具都带一个可选的「说一句」参数，放在第一个，说明写在工具定义里：「用一句话告诉用户你发现了什么、接下来做什么」。它调用工具时顺手填上，系统先把这句话显示出来，再去执行。这样所有支持工具调用的模型都能用，不依赖模型「动手前会不会自己说话」，也不会为了说一句话多跑一趟。

- 「升级」本身也是一次工具调用，所以交给高档之前那句（「拉到了，这个对比要仔细想一下」）同样有地方放。
- 一步里同时调了几个工具时，只显示第一句。
- 不填不拦：它没填，系统根据它正在做的事补一句平实的话。
- 没有采用「单独一个说话工具」的做法：模型如果把它单独调用，每句话就要多等一次往返。

**高档任务先列清单，做完一项打一个勾。** 问题被判为需要高档时，接手的高档第一件事是把要做的事列成一张清单，显示在对话里；每做完一项打勾，正在做的那一项下面仍然是它边做边说的话。

```text
☑ 1 拉取微软和英伟达最近一季的财报
☑ 2 各自整理营收、利润率、指引
◐ 3 对比两家的数据中心业务
     英伟达这部分单独披露，微软要从智能云里拆，我先看附注。
☐ 4 对比资本开支和指引
☐ 5 写结论
```

- **清单是它用一个工具写的，勾由系统来打。** 它每次调用工具时顺手标一下「这是为清单第几项」，系统据此把那一项标成进行中、把上一项打勾，回答出来时收尾。它中途要加一项、去掉一项或标一项失败，仍然直接改清单，清单上如实显示。（11-24 实测后改：原先让它每做完一项自己回来更新，两次实测里它都只列一次、不回来打勾。）
- **你可以对着清单插话：** 「第四项不用做了」「再加一项看现金流」。
- **做完后清单收成一行**（「5 项，2 分 10 秒」），点开还能看。
- **转到后台的任务同样有清单，** 你问「手上有什么事」时看到的就是这些清单和进度。
- **低档和中档不列清单，** 只有边做边说的话。这些问题几步就完，列清单反而慢。

**各通道上的形态：**

| 通道 | 边做边说的话 | 清单 |
|---|---|---|
| 网页 | 逐句叠在回答上方，答完收成一行 | 显示在对话里，实时打勾 |
| Telegram | 逐句加进同一条可修改的进度消息，正式回答另发一条（这样会有通知） | 放在那条进度消息里，打勾就是改这条消息 |
| 微信 | 不能修改已发出的消息，每句都是一条新消息，所以最多发一句：一轮超过 10 秒还没答完时，发它当时最新的那句。几秒就答完的不发。形态待 owner 试用后定 | 开头发一次清单，中间不逐项通知，做完发回答 |

### 4.6 分派：跑腿派出去，判断留在自己手里

升级（4.4）是把「想」往上交，分派是把「跑腿」往下派，两件事分开：

- 互不依赖的跑腿活（拉取、读原文、摘数字）同时进行。现在一步里的多个工具调用是一个接一个执行的，改成并行，拉微软和拉英伟达就能同时跑。
- 一项跑腿活本身要好几步时（比如读三份电话会、各摘出资本开支的说法），派给一个低档的小助手去做。它只拿到一段简短的交代和用得上的工具，做完交回结果和出处。
- 对比、判断、写结论不派出去，由对话线上当前的那一档自己做。它手里有全部上下文和你的意图；把判断派给一个新开的助手，就得重新交代一遍，信息会在转手时丢。

**先做并行，小助手随后。** 「拉取」本身是一次调用就能完成的事，所以第一阶段靠并行就能拿到大部分好处。小助手多一种出错的方式（交代不清、结果转手时丢信息），所以放到第三阶段，用尺子量过质量再默认打开。这个顺序出于工程风险，不是为了省钱。

### 4.7 插话

它干活时你发来的任何一句话，系统立刻显示「已收到」，然后在它当前这一小步结束时交给它，由它判断：

| 情况 | 它怎么做 |
|---|---|
| 补充或修正 | 按新说法调整，已查到的资料保留 |
| 另一件事 | 另起一件事同时做，原来那件继续，各自答完各自回 |
| 改主意 | 立即停下 |

- 如果它正在写回答：停笔，把写了一半的内容和你的新消息一起给它，由它决定并进去重写，还是把新事另起、把原回答接着写完。
- 每条回答上方带一行引用，标明它对应你的哪句话。
- 同时进行的事默认最多三件，再多就排队并告诉你。

### 4.8 交办

每件事都有一个状态：进行中、完成、失败、已停。你可以随时问「你手上有什么事」。每件事结束时一定有一条消息，失败也要说清楚失败在哪。耗时长的事自动转后台，你不用守着页面，做完它在对话里说，并按你的设置推到你的通道。

### 4.9 出错时怎么办

- **模型服务出错或超时：** 重试一次；仍失败就换到你预先指定的备用模型，并在回答上标明「这条由备用模型回答」。现在没有备用，出错就是整轮失败。
- **工具失败：** 它如实说哪一步没拿到、因此哪部分答不了，不拿旧数据冒充。
- 每一种失败都有一句人能看懂的话，不出现错误代码。

### 4.10 它是谁、怎么说话

「活人感」和「懂你」有一半取决于系统说明怎么写。现在的提示词是一条条规则累积出来的，新内核重写一份短的：

- 它是你的金融助手，说话像一个可靠的同事：结论先说，不绕，不堆免责声明。
- 可以给看法供你参考，决定权在你；永远不替你下单。
- 没有的就说没有，不确定的说清楚不确定在哪。
- 所有希望它遵守的规则都写在这份说明里。没写进去的规则不算数，代码不因为它没猜到而罚它。

### 4.11 它知道自己知道什么、截至什么时候

来由：11-23 英伟达宣布黄仁勋复任 CEO。公告 22:02 就进了系统的库，owner 22:43 问起时，它五次查询全是网页搜索，没有看库里的公告，还用盘前的旧报道否定了 owner 看到的新消息。哨兵当晚倒是发了三条英伟达的异动提醒（21:56、22:06、23:21，第二条写着「较昨收涨 27.9%，约 7.1σ」），但都只有涨幅，没有原因；而原因（那份公告）在第二条提醒发出前 4 分钟就已经在库里了。盯价格的和收公告的是两套东西，互相不知道。

这三处表面上是三个问题，根子是同一个：**它不知道系统手里有什么，也不知道自己手里的资料是什么时候的。** 靠在提示里加「记得先查库」「记得写截止时间」解决不了，那是让模型去记规矩，换一种情况还会漏。下面三条是结构上的做法，由系统保证，不靠它记得。

**1. 系统知道的，它一定看得见。**
一句话里提到某个关注对象时，系统自动把这个对象的「最新掌握」放进这一轮的背景里：最近的官方公告、最近的新闻、最新价格，各带时间。它不需要决定「要不要去查库」，因为库里的新东西已经在眼前。工具只用来拿系统还没有的东西。

```text
关于 英伟达（NVDA），系统最新掌握：
  官方公告  11-23 22:02  8-K：董事会决定黄仁勋复任总裁兼 CEO   ← 41 分钟前
  新闻      11-23 21:40  盘前芯片股反弹……
  价格      11-23 22:42  较昨收 +29.8%
```

**2. 时间是一等信息。**
- 每条资料都带发布时间，工具结果里由系统算好并写明「这批结果里最新的一条是多久以前的」。
- 你说的话也是一条资料，时间是「现在」。它手里的资料比你的说法旧时，不能用旧的否定新的。
- 你的说法和它手里的资料对不上时，它的任务是往更权威的来源去核实，而不是下结论。来源的先后由系统给出：官方备案和公司新闻稿，其次通讯社和主流媒体，其次聚合站，最后才是社交平台和通用网页搜索。
- 回答里写明资料截至何时，这是上面几条的自然结果。

**3. 异常必有解释。**
硬保证不用清单来列（高管变动、并购、业绩预告……永远列不全），改用结果来兜底：
- 关注对象出现异常的涨跌或成交量时，系统强制叫醒它去查原因，并且必须给你一个交代：要么是「因为某公告」，要么明说「没查到原因」。
- 关注对象的每一份新的官方公告默认都告诉你；它判断不值得打扰时，要记下理由（7.2 的沉默记录）。
- 这样即使某类事件没人想到过，只要它引起了价格异动，或者它是一份官方公告，就不会被漏掉。
- 异动提醒本身也要带原因：发提醒时先看档案里这个对象最近的公告和新闻，有就写上，没有就明说「原因还没查到，我在查」，查到后补一条。

这个例子进题库，并作为「那天如果它在」（7.5）的第二个回放场景：22:02 公告入库，看它在几点几分告诉你什么。

## 五、档案

档案是整个方案里最大的新东西，「快」和「可靠」都靠它。

**对象：** 先做公司。结构上预留行业、主题、宏观指标，这一期不做。

**每份档案四部分：**

| 部分 | 内容 | 谁维护 |
|---|---|---|
| 事实 | 各期财务数字、标准比率、同比环比、指引、最新财报摘要、最新价、近期事件 | 系统，后台自动 |
| 你的看法 | 你对它的判断、理由、什么情况会让你改主意、你的计划 | 你说，它记；保留历史版本 |
| 盯防条件 | 对你来说什么算异动，用你自己的话写（第七节） | 你说，它记；它也会从反馈里学 |
| 往来 | 它推给过你什么、你问过什么、当时的结论 | 系统，链接到对话原文 |

**怎么建：**

- 财报、公告、行情一入库，后台就更新对应档案，不等你问。
- 你问到一家还没有档案的公司，它现场拉取、整理、回答，顺手存下，下次直接答。
- 谁有档案：你的持仓、研究队列、问过的公司。

**把核对从回答时挪到入库时。** 每个数字写进档案之前，由代码对着原文核对；比率和同比环比由代码计算，并记下是由哪两个数字算出来的。核对不过的不写成事实，只保留原文供查阅。这样档案里的每个数字都自带出处，回答时直接引用，不需要再查一遍。新闻稿数字那一块（已上线）已经是这个做法，这里把它推广到全部。

**数据源是可替换的一层。** 和消息通道一样，内核不关心数据从哪家来。

- **要接的更多数据：** 一致预期、电话会全文、内部人交易、机构持仓、宏观日历。一致预期排第一，因为「事前准备」（第七节）要用。面向从业者时，数据的广度会成为门槛。
- **已知缺口：实时行情。** 面向短线用户时，现在分钟级轮询的免费数据不够新。这一期不解决，以后接付费实时源不用改内核。在此之前，回答里的价格都标明数据时间。

## 六、记忆

### 6.1 三种记忆，各放各的地方

| 记什么 | 放哪 | 现状 |
|---|---|---|
| 关于你：偏好、背景、给它的长期指示 | 个人记忆条目 | 已有，但几乎没有自动产出 |
| 你对每个关注对象的看法 | 档案的「你的看法」 | 新增 |
| 对话原文 | 消息表，一字不改 | 已有 |

两条规矩：

1. **细节只从原文来。** 摘要只是目录，用来找到是哪一轮；回答细节时必须读回那一轮的原文。这是「记得准」的保证。
2. **你明说的记忆必须有你的原话作依据。** 这条现在就有（记忆条目要能在你的消息里找到出处），保留。

### 6.2 更新节奏：当场、每月、每季

| 层 | 记什么 | 什么时候更新 | 怎么来的 |
|---|---|---|---|
| **当场** | 你明说的：偏好、指示、看法（「以后财报先给我三句结论」） | 这件事做完就记，在对话里说一声「我记下了：……」，一句话可撤销 | 你的原话，带出处 |
| **每月整理** | 画像：你没明说但反复出现的习惯（总是先看同比、常在周一早上问持仓）；近期关注的方向 | 每月一次，或新对话攒够一定数量时，先到为准 | 它从这段时间的对话里归纳，每条附上几次例子，标为「我的推测」 |
| **每季沉淀** | 长期记忆：稳定的东西（你的角色、风格、风险偏好、长期持有的理由） | 每季一次，和财报季对齐 | 从月度画像里挑出持续成立的；过时的归档 |

- **为什么要有「当场」这一层：** 只按月抽取的话，你昨天交代的事它今天还不知道，「懂你」就不成立。按月、按季的整理解决的是另一类问题：单独一轮对话看不出来的规律，以及记忆越积越乱。
- **明说的和推测的分开。** 你说过的直接生效。它推测的先轻用（影响回答的详略和顺序，不影响结论），并在每月整理后告诉你「这个月我对你的了解多了这几条，对吗」，你确认后才算正式记忆。
- **推测由它当场记，不另设旁路（11-26 定）。** 对话里的模型看出你没明说的稳定习惯时，当场记成一条推测（引用你在这段对话里的原话，代码核对确实是你说的），并用一句话告诉你；每月整理把这些推测和它新归纳的一起拿给你确认。原来「每轮结束后另一个模型只看你一句话、再由第三个模型打分」的抽取不再用于新内核。读过网页、公告等资料的那一轮，只有推测能直接记，明说的记忆照旧走确认卡（防止资料里的话借你的引用写进记忆）。
- **新的盖旧的，旧的不删。** 说法前后矛盾时以最近一次明说的为准，旧的归档，能查到你什么时候改的主意。
- **会过期。** 每条记忆带「最近一次被印证」的时间。卖掉的持仓、很久没再出现的习惯，在季度沉淀时归档。
- **每月给你一份变更说明：** 新记了几条、改了几条、归档了几条。
- **节奏可配置。** 每月、每季是默认值；用得多的人可以调短。

### 6.3 建在记忆之上的三件事

| 事项 | 内容 |
|---|---|
| **它眼中的你** | 一页列出它记住的关于你的一切和它的推测，可以改、可以删、可以整体导出。「放心把信息交给它」需要这一页 |
| **复盘** | 每季沉淀时一起做：回看你以前的判断，哪些成立了，哪些没有，当时的理由还在不在。依赖「你的看法」有了历史版本 |
| **角色模板** | 「短线」「定投」「基金经理」各一套起步设置：盯防条件、简报格式、常用技能。只是初始的记忆和配置，不是代码分支，内核仍然不认识任何一种用户 |

## 七、后台值班：规则负责叫醒，它负责判断

要求：有事要它来通知，而且是它在判断，不是一组规则在发消息。

**现状：** 价格异动和新闻推送是纯规则（超过几倍波动、命中关键词就发）。财报那条线有模型在读原文。定时任务是按时间表唤醒它跑一轮。没有一个「有事发生，它结合对你的了解来判断」的通用环节。现有的零件都保留：哨兵、财报监控、官方公告监控、新闻轮询、例行任务。

### 7.1 三层

```text
感知（代码，一直在跑）──事件──→ 判断（它，被叫醒，带着你的档案）──→ 投递（通道，可升级）
```

1. **感知。** 公告、价格、新闻、日历、你设的条件，都由代码盯着。规则留在这一层，但职责变了：以前是决定「发不发」，现在只决定「要不要叫醒它」。所以规则可以放宽，宁可多叫几次。
2. **判断。** 事件先进档案。它被叫醒时看到：发生了什么、你的持仓和关注、你对相关对象的看法、你交代过的盯防条件、它最近已经告诉过你什么、你对以往提醒的反馈。必要时先查一下（读公告原文、看盘后反应），然后决定四选一：马上告诉你、攒进下一次简报、只记进档案、不理会。要告诉你时，用它自己的话写：发生了什么、为什么和你有关、和你的判断有没有冲突、你可能想做什么。
3. **投递。** 走第八节的通道层，紧急的没确认就升级。

### 7.2 关键设计

- **盯防条件用自然语言。** 你在对话里说「帮我盯着英伟达数据中心收入的指引」「有出口管制的新消息告诉我」，它记进档案。这种条件规则写不出来，只有它读了内容才能判断，这是「它在值班」和「规则在推送」的根本区别。
- **默认每件事都叫醒它。** 花费不作为设计约束。保留的区分只在怎么告诉你：紧急的马上说，不急的由它攒进简报。叫醒频率做成可配置，想省的人可以调成隔一段时间统一过一遍。
- **重要的事分两句说。** 先在几秒内说一句「英伟达财报刚出，我在看」，一两分钟后再说读完的结论。前一句不需要深想，后一句才需要。
- **你明确要的一定到。** 你亲口设的价位、持仓的财报，这些是硬保证：它可以补充说明，但不能决定不发。它的判断是在这之上加东西，所以它判断失误不会造成漏报。
- **异常必有解释，官方公告默认告知。** 硬保证不靠事件清单，靠结果兜底：关注对象出现异常涨跌必须给出原因或明说没查到；每份新的官方公告默认告诉你，不告诉要记理由（见 4.11）。
- **每天自查一次漏报。** 对照当天应该发生的事（财报日、你设的价位）和实际发出的提醒，漏了就补发并说明。英伟达 11-17 那次就是这样漏的。
- **沉默也留记录。** 它看到了但决定不打扰你的事，记一行原因。每天的简报里有一句「今天替你过滤了 12 条，点开看」。这样一周没消息时你知道它在干活，也能发现它过滤错了什么。
- **每条提醒带「有用／没用」。** 用来调整打扰的阈值，也是尺子的数据来源。
- **它记得自己说过什么。** 不重复提醒同一件事；有后续时说「上次告诉你的那件事有更新」。
- **它答应的事也是叫醒它的理由。** 「周五提醒我看通胀数据」「做完来找你」，到点叫醒它去兑现。
- **事前把活干了。** 财报一出，它被叫醒时顺手把档案更新好、把和你看法的对照准备好。你之后追问，直接有答案。

### 7.3 什么算异动（11-24 按实际提醒记录重新设计）

**现状（哨兵 11-03 到 11-24 的全部记录）：** 21 天发了 65 条，其中英特尔 38 条（唯一的持仓，所以所有规则都对它生效）。能读出涨跌幅的 41 条里，15 条相对昨收不到 2σ，也就是这只股票自己的日常波动之内。问题出在四处：

| 现在的规则 | 实际效果 |
|---|---|
| 5 分钟内的涨跌超过「这个时段 5 分钟波动」的 4 倍就提醒，下限 1% | 盘前成交稀薄，5 分钟波动的基准只有 0.2% 到 0.3%，所以「5 分钟跌 1.0%」会被算成 4.5σ。对一只日波动 7.5% 的股票，这不是事 |
| 提醒过一次后，每再走 3% 就再提醒 | 3% 对英特尔只有 0.4σ。出现过「较昨收涨 1.9%（约 0.3σ），今日第 3 条」 |
| 价格穿过预设价位就提醒 | 在 55 元上下来回，一周提醒了 5 次同一个价位 |
| 所有提醒一个样子 | 英伟达涨 36%（9σ）和英特尔 5 分钟跌 1% 看起来同样重要，都没有原因 |

**新的做法：先量清楚，再分级，每级只说一次，说的时候带原因。**

1. **用三个量描述一次波动，都由代码算：**
   - 相对它自己：今天相对昨收，是它日常波动的几倍（日 σ）。这是主要依据。
   - 相对大盘和同行：同一时间大盘、同板块涨跌多少。用来分清「它自己的事」和「大家一起动」。
   - 对你的影响：持仓的话，这一下是你总资产的百分之几。

2. **分三级，决定怎么告诉你：**

| 级别 | 条件（默认值，可调） | 怎么处理 |
|---|---|---|
| 记录 | 不到 2σ，也没有新公告 | 不打扰，进当天的简报 |
| 值得知道 | 2σ 以上；或者有新的官方公告；或者第一次穿过你设的价位 | 发一条，带原因 |
| 重大 | 4σ 以上；或者穿过止损价；或者持仓的这一下超过总资产的 2% | 立刻发，带原因，没确认就升级 |

3. **每一级每个方向一天只说一次。** 不再按固定的 3% 一步步追着报。从「值得知道」升到「重大」时再说一次；明显反转（回吐一半以上）时说一次。昨晚英伟达那种走势会是两条，不是三条；英特尔大多数日子是零条。

4. **价位提醒要「上锁」。** 穿过一次就提醒一次，之后要离开这个价位一段距离（默认半个日 σ）才重新生效。再次穿过时写明「第几次」。

5. **5 分钟急涨急跌默认关闭，** 做短线的人在角色模板里打开。打开时也要同时满足「这 5 分钟超过半个日 σ」，盘前要有成交量佐证。

6. **大家一起动时合成一条。** 「芯片股普涨，你关注的 5 只涨 6% 到 36%，其中英伟达是因为……」，而不是一只一条。

7. **原因由它来查，只在「值得知道」和「重大」两级才叫醒它。** 按上面的分级，这两级一周只有几次，所以不是每次波动都调用模型。它先看档案里这个对象最近的公告和新闻（4.11），有就写上；没有就先发「原因还在查」，查到补一条。

8. **灵敏度给你一个三档的开关：** 安静、标准、灵敏，对应不同的 σ 门槛。不让你直接调 σ。每条提醒的「有用／没用」用来微调。

**你自己定的规则优先（owner 11-24 提出）。** 上面的分级只是默认值。你可以在对话里直接说什么时候提醒你，比如「英特尔涨跌 10% 提醒我，20% 加急」「成交量到平时的三倍提醒我」。系统要接得住：

- **它把你的话翻成一条明确的规则，先给你确认。** 一句话常有几种读法：「涨跌 10%」是相对昨收、相对你的成本，还是从今天起累计？确认卡上写清它的理解，例如「英特尔相对昨收涨或跌达到 10%：提醒；达到 20%：加急。每天每档一次」。你点了才生效。
- **规则由代码每分钟检查，不用模型。** 翻译只在你定规则时做一次。规则能用的量：涨跌幅（相对昨收、开盘、你的成本、某个价位、近 N 日）、价格、成交量（绝对值或相对平时的倍数）、持仓盈亏额、占总资产比例；加上比较、时间范围、级别（提醒或加急）、重复方式、有效期。
- **代码量不了的条件交给它判断。** 「有出口管制的新消息告诉我」这类要读内容的，保留原话，在相关事件发生时由它来判断（7.2）。
- **盯不了的要明说。** 系统没有的数据（比如期权隐含波动率），它直接告诉你盯不了，不能假装记下了。
- **定规则时先用历史试跑。** 确认卡上写一句「按这条规则，过去 30 天会提醒你 3 次：11-05、11-17、11-23」，你一眼能看出它是太吵还是太钝。
- **你定了规则的股票，以你的规则为准，** 默认分级不再对它生效；没定的继续用默认值。重大公告和止损价这类硬保证不受影响。
- **每条提醒写明是哪条规则触发的，** 例如「按你 11-24 定的规则：英特尔涨跌达 10%」。
- **随时能问、能改：** 「你现在帮我盯着什么」列出全部规则；改和删也是一句话。规则存在档案的「盯防条件」里，也出现在「它眼中的你」那一页。
- 现在的补仓价、止损价、目标价就是这种规则的三个特例，并进同一套。角色模板（6.3）就是预置的一组规则。

**两套规则并行（owner 11-24 定）。** 一套是你自己定的，一套是系统按从业者的眼光预置的。

- **预置的那一套对你完全公开，你可以改。** 问「你现在帮我盯着什么」时，两套都列出来，预置的标明「系统默认」。每一条都能关掉、能调门槛；你改过的那条就变成你自己的规则。你不用去设计它，但它不能是一个你看不见的黑箱。
- **你对某只股票定了规则，同一类的默认规则让位，其他类的照常。** 例如你定了英特尔的涨跌幅规则，默认的涨跌幅分级对它不再生效，但默认的成交量异常、新公告、连续多日下跌仍然在盯。规则之外的异常不单独打扰，放进当天简报。

**预置规则一定会有遗漏，所以不靠「列全」来保证。** 任何清单都列不全，靠下面四层兜住：

| 层 | 管什么 | 为什么能兜住没想到的情况 |
|---|---|---|
| 统计异常 | 价格、成交量、相对同行的表现，只要明显偏离它自己的历史就算，不问原因 | 不需要事先知道是哪类事件，只要它反映到了交易上 |
| 官方公告 | 关注对象的每份新公告默认告知 | 不需要事先列出公告类型 |
| 它读内容来判断 | 新闻和公告对照「你的看法」和你用自然语言写的条件 | 能发现不影响当天股价、但动摇你持有理由的事 |
| 事后复盘 | 每次大波动之后查一遍：之前有没有提醒、提醒里有没有原因。你说一句「这事怎么没告诉我」也会记下来 | 漏掉的会变成一条新规则或一道题，同样的事不漏第二次 |

**预置规则打算覆盖的方面**（现在的哨兵只有前两项的一部分）：

| 方面 | 例子 | 现在有没有数据 |
|---|---|---|
| 单日涨跌 | 相对昨收的 σ 倍数、跳空 | 有 |
| 成交量 | 是平时的几倍 | 有 |
| 多日累计 | 连续下跌、五日累计跌幅。每天跌 3% 连跌五天，单日规则一次都不会响 | 有，规则没做 |
| 相对大盘和同行 | 大盘涨它跌 | 要配板块基准 |
| 关键位置 | 52 周新高新低、长期均线 | 有，规则没做 |
| 公告和日历 | 各类 8-K、内部人买卖、财报日、除息日 | 部分有 |
| 你的组合 | 单只占比过高、总资产回撤。现在英特尔占你总资产四成多，没有任何规则提这件事 | 有，规则没做 |
| 盘前盘后 | 财报后的盘后大幅波动 | 有 |
| 评级、做空比例、期权异动、宏观数据日 | | 没有数据源 |

最后一行现在盯不了，会在规则列表里如实写明「暂无数据」。

**上线前先回放。** 用过去三周的行情把新规则跑一遍，看会发几条、发的是哪几条，和实际发出的 65 条对照，确认该发的没漏（英伟达 11-23、英特尔 10-30 那种）再换上去。

哨兵在新骨架里是保留的部分，所以这一节的规则部分可以现在就做，不用等新内核；「带原因」那一步依赖档案，可以先用现有的公告和新闻库做一个简化版。

### 7.4 事前准备

财报前一晚主动说：明天谁出财报、上次指引是多少、你的看法是什么、这次重点看什么。每周一给一份本周日历。这需要一致预期的数据源（第五节），所以排在它接上之后。

### 7.5 验收方式：那天如果它在

拿历史上的某一天按时间回放，比如英特尔 10-29 那次财报，看它会在几点几分通知你什么。这既是值班功能的验收方式，也是最直观的对外演示。

### 7.6 风险

- **它判断错。** 过滤掉了该说的：靠硬保证和漏报自查兜底，靠沉默记录发现。说了不该说的：靠「有用／没用」的反馈调整。
- **延迟。** 判断要几秒到一两分钟，所以重要的事分两句说。
- **花费。** 不作为设计约束。每次叫醒是一次模型调用，用量里单独列出「值班」这一项，让使用者自己看、自己调。

## 八、消息通道

### 8.1 通道是可替换的一层

内核不知道消息从哪来、发到哪去。网页、Telegram、微信都是通道，可以替换和增加。

- **一条对话线，多个通道。** 你从哪个通道发来的话，都进同一条对话线；它从你提问的那个通道回你。
- **主动消息按紧急程度选通道。** 普通的发到你的常用通道；紧急的如果没被确认，换下一个通道再发，直到你确认。
- **每条主动消息有投递记录：** 已发出、已送达、已确认。「提醒发了没有、你看到没有」可以查。

### 8.2 现状

- **Telegram：** 对话和提醒都走它。近 30 天绑定 1 个，定时任务 1 个，财报事件 3 次，收件箱条目 14 条。回国后不能直接用。
- **微信：** 11-22 上线（PR #20）。owner 的备用号扫码接入 ClawBot，微信里可以和默认 bot 对话，`@名字` 转给指定 bot，真实对话验证正常。只能对话，提醒还没接到微信。
- **手机强提醒（Pushover）：** 没有配置。
- **缺的：** 两个桥是各写各的，还不是统一的通道层；提醒发件箱是 Telegram 专用的；没有备用通道，也没有「没确认就升级」。

### 8.3 微信的几条途径

| 途径 | 你用什么收 | 能否主动推送 | 接入条件 | 适合 |
|---|---|---|---|---|
| **微信 ClawBot 插件**（2026-03 推出，已接入） | 个人微信，像一个联系人 | 部分已实测，见下 | 扫码登录，长轮询，不需要公网地址 | 个人用户 |
| **企业微信智能机器人**（API 模式，长连接） | 企业微信 | 能，但你要先给它发过消息 | 要有一个企业微信组织；不需要公网地址 | 团队、金融公司 |
| **企业微信自建应用 + 微信插件** | 个人微信或企业微信 | 能，随时 | 要固定公网 IP 加白名单，还要验证公司名下的域名 | 有 IT 的公司 |

另有「微信客服」：只能在对方发消息后 48 小时内回最多 5 条，不适合做提醒。

**ClawBot 已知和未知的：**

- **已实测（11-22）：** 能收；能带凭据回复；你最后一条消息 10 分钟后带凭据主动发，能到。
- **没有测：** 1 小时、24 小时、72 小时之后还能不能到，以及不带凭据能不能到。协议上，发消息要带一个随你上一条消息下发的凭据，它隔多久失效，查到的资料都没说。owner 决定不单独测，接上主动提醒后用真实提醒来观察。
- **账号风险：** 这个插件是为 OpenClaw 做的。我们是照着腾讯公开的插件源码自己实现的，没找到腾讯允许这样用的说明。owner 用的是备用号，已接受这个风险。
- **覆盖面：** 推出时在灰度，要求 iOS 微信 8.0.70 以上，不能进群。安卓和全量的现状没有核实。
- **登录会失效。** 失效时桥暂停一小时，并在 Telegram 提醒，需要重新扫码。

### 8.4 下一步

1. **做成统一的通道层**（阶段 1）。Telegram 桥和微信桥并进去，提醒发件箱改走通道层，这样微信也能收到提醒。
2. **用真实提醒观察微信的长间隔推送。** 能到，微信作为国内的主通道；不能到，微信只用来对话，提醒走手机推送。
3. **配一个手机强提醒通道作为兜底，** 不管上一条结果如何。Pushover 之前就计划过；iOS 上还有 Bark 这类推送应用可选（这一条是我已有的了解，没有核实）。
4. **企业微信放到面向公司客户时再做。** 金融公司大多已经在用企业微信，助手直接在里面，对他们是顺手的。

## 九、留痕和后台

### 9.1 留痕：回答之后再核对，只标注

回答先给你。发出之后，后台把回答里的数字和档案、工具结果逐个对上，对不上的在那句话旁边加标注，并存下来供事后回放。

- 不拦截、不删句、不重写。
- 现有的核查代码约 8,800 行，大部分是为了在回答发出之前拦住和重写。挪到旁路之后，保留「数字对账」和「出处编号」两块，其余退役。
- 这和仓库三条准则一致：默认相信模型，有疑问如实标注，让你自己判断。
- 对金融公司，这份留痕就是合规和复盘要看的东西。

### 9.2 后台：所有记录收在一处

留痕分两处给人看：

- **对话里：** 每条回答可以点开「依据」，看到出处和对账标注。这是给提问的人看的。
- **后台：** 一个专门的页面，给负责运维、改进和合规的人看。个人用户就是 owner 自己；卖给公司时是管理员和合规人员。

| 栏 | 看什么 |
|---|---|
| 回答 | 每一件事的完整经过：问了什么、哪个模型、哪一档、每一步说了什么调了什么、用了哪些出处、数字对账结果、耗时 |
| 值班 | 每次被叫醒：因为什么事、它怎么判断的、发没发、没发的原因 |
| 提醒投递 | 每条主动消息：发到哪个通道、送达没有、你确认没有、有没有升级 |
| 记忆变更 | 记了什么、改了什么、归档了什么，各自的依据 |
| 操作记录 | 它替你做过的每个写操作：谁在什么时候点的确认 |
| 用量 | 每件事用了哪个模型、哪一档、花了多少；按天、按模型、按 bot、按用途（对话、值班、整理）汇总 |
| 质量 | 被点「不好」的回答、每周自检的归类、尺子的历次成绩 |

- **能筛、能搜、能回放。** 常用的筛选：数字没对上的、失败的、被点了不好的、用了高档的、耗时最长的。点进一条能按时间顺序重看整个过程。新内核的对话是只往后追加的，这份记录本身就是完整的经过，后台只是把它显示出来。
- **只读。** 后台不能改记录。个人版 owner 可以删除自己的数据；公司版不能删，只能按设定的期限自动过期。这一条做成可配置。
- **能导出。** 一条回答的完整经过可以导出成一份文件，给合规或复盘用。
- **用量看得见，上限可选。** 月度花费上限是可选配置，默认不设；设了的话，到了先提醒，再停高档。之前对着模型服务商的控制台对不上账的问题，在自己的页面里就能看清。
- **和现有工具的分工。** 模型调用的原始细节仍在 Langfuse 里，后台里放一个跳转链接，给开发的人用。产品层面的记录（对账、确认、反馈、投递）放在自己的后台，因为合规人员不该去用开发工具。
- **什么时候做。** 「回答」这一栏在第一阶段就做最小版：现在排查问题要到盒子上查数据库，有了它开发也省事。其余各栏随对应的功能一起上。导出和保留期限放到面向公司客户时做。

## 十、尺子和持续改进

### 10.1 尺子

先于一切动工。没有它，后面每一步都只能凭感觉。

- **内容：** 六十条左右真实问过的问题，覆盖：简单事实、财报简述、多公司比较、追问、回忆细节、插话、交办。每条附上应当出现的关键数字或要点。
- **量什么：** 七条承诺各自的指标，加上每轮花费和工具调用次数。
- **怎么用：** 旧流程先跑一遍作为基线；之后每个阶段，新内核和旧流程用同一个模型各跑一遍对比。跑评测用便宜的模型。

### 10.2 用真实反馈持续变好

- **每条回答可以点「好／不好」，** 点「不好」时可以说一句原因。提醒有「有用／没用」（第七节）。
- **点了「不好」的问题自动进入尺子的题库，** 下次改动必须把它答好。题库来自真实使用，不是我想出来的题，这是「可持续优化」的来源。
- **每周自检报告。** 把被点「不好」的回答归类：缺数据、工具选错、想得太浅、记错了你的偏好。每周一份，告诉我们下一步该改哪里。

### 10.3 访客模式和对外展示

- **访客模式保留，作为公开演示：** 不登录能问公开数据的问题，看不到任何个人数据，有每日次数上限。
- **每个阶段结束，尺子留下一份改前改后的数字。** 全部做完后写一篇讲清取舍的说明，更新 README。加上「那天如果它在」的回放（7.5），这些是求职时能直接给人看的材料。

## 十二、怎么落地

**做法比较：**

| 做法 | 好处 | 代价 |
|---|---|---|
| **在旁边搭新内核（选这个）** | 线上始终可用；每个 bot 单独切换，随时退回；新旧可以用同一批问题对比 | 一段时间内两套并存 |
| 在原处一步步改 | 每步风险最小 | 就是前几次打补丁的路，预先分类这一步不拆，插话和「只想一次」做不成 |
| 新开仓库整个重写 | 最干净 | 丢掉三千八百多条测试记下的经验；线上要停 |

选第一种是我的判断：你把怎么做交给了我，而且它是唯一能边做边用、边做边量的做法。

**阶段：** 每一阶段都能单独上线、单独验收、单独退回。

| 阶段 | 做什么 | 验收看什么 | 大小 |
|---|---|---|---|
| 0 | 尺子，旧流程跑出基线；「好／不好」反馈接进题库 | 有一份基线报告 | 小 |
| 1 | **新内核最小版，只给测试 bot 用。** 追加式循环和历史预算；十来个工具（先包住现有功能）；写操作三级；低档接住、需要时升级；工具并行；边做边说和高档清单；出错处理和备用模型；新的系统说明；通道层（Telegram、微信并进去，提醒也能发到微信）；「被事件叫醒」的入口；后台「回答」栏和用量记录的最小版。同时把 90 个改数据的接口过一遍，列出差距 | 回得快、看得见，对比基线 | 大 |
| 2 | **档案。** 公司事实、入库时核对、财报摘要、现拉现存；提到关注对象时自动带上「最新掌握」；资料带时间和新旧标注（4.11 的前两条） | 「英伟达最新财报简单说说」10 秒内；计算调用次数大幅下降 | 大 |
| 3 | **插话和交办。** 状态、后台任务、多件事并行；小助手分派；操作目录补全并加上「不漏」的自动检查 | 能插话、交得出去；它做不了的操作清零（豁免项除外） | 大 |
| 4 | **记忆。** 你的看法、读回原文、当场记、每月整理、每季沉淀、「它眼中的你」。之后接着做角色模板和复盘 | 懂你、记得准 | 大 |
| 5 | **后台值班和留痕。** 规则只负责叫醒、它来判断、自然语言盯防条件、硬保证、沉默记录、漏报自查、提醒反馈、投递记录和升级；事前准备（等一致预期数据接上）；留痕旁路；后台其余各栏 | 可靠；提醒有用率；「那天如果它在」回放 | 大 |
| 6 | 所有 bot 切到新内核，删除旧流水线；写对外说明，更新 README | 尺子全项不低于基线 | 小 |

**贯穿各阶段的两件事：**

- **更多数据：** 按数据源接口逐个接，一致预期排第一。
- **每周自检报告：** 阶段 1 之后开始出，依赖「好／不好」的反馈。

阶段 1 和 2 做完，你就能感觉到明显不同。我没有写日期，因为阶段 0 的基线出来之前，任何日期都是猜的。

## 十三、这一期不做

- 不执行交易，永远不做。
- A 股和港股。数据源做成可替换的，但这一期只有美股。
- 付费的实时行情源。
- 多人、团队、公司三层权限。数据上保留「属于谁」，不做团队功能。
- 企业微信，以及后台的导出和保留期限。面向公司客户时再做。
- 云电脑式的通用操作。

## 十四、风险和我没把握的地方

1. **去掉预先分类后质量会不会掉。** 现在的分类表挡掉了一些错误用法。靠尺子盯，不靠猜。
2. **低档把难题看简单。** 提示里写明拿不准就升级；每条回答标出档位；判错的比例由尺子统计。
3. **缓存的效果各家不同。** Claude 直连的缓存我们已经在用；DeepSeek、智谱、OpenRouter 上的缓存行为我没有逐家核实，阶段 1 要先测。
4. **有的模型不填「说一句」。** 这时由系统补一句平实的话，活人感会差一些。哪些模型会这样，阶段 1 实测才知道。
5. **「2 秒内出第一个字」取决于模型和线路。** 这是目标，不是保证，由阶段 1 的实测来定。
6. **盒子的承受力。** 大部分时间在等模型返回，应当够用；并行、后台任务和每件事都叫醒的值班上线前，要在盒子上实测内存。
7. **微信长间隔的主动推送还不知道行不行，** 备用号也可能被限制（第八节）。
8. **花费不作为设计约束。** 默认按效果最好的来；影响花费的地方都做成可配置项：值班的叫醒频率、同时进行的件数、小助手开关、最高档的使用、备用模型、花费上限、记忆整理的节奏。入库时写财报摘要、值班的每次叫醒、每月的记忆整理都会多调模型，记进用量即可。
